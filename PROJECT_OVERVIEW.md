# suslicke.com — личный сайт + hub

## Что это

Личный бренд-сайт Андрея Пустового (`suslicke.com`) вместе со вспомогательным
бэкенд-сервисом **suslicke-hub**. Проект состоит из двух частей:

- **`web/`** — публичный сайт на Next.js: мультиязычная (RU/EN) лендинг-страница
  с «персонами» (разные версии контента под разную аудиторию — бизнес, HR,
  разработчики, обычные посетители), 3D-сценой на Three.js (частицы, из которых
  складывается силуэт суслика и переходит в другие фигуры), тёмной/светлой темой,
  vCard, SEO-разметкой и аналитикой с баннером согласия.
- **`hub/`** — Python-бэкенд на FastAPI + Telegram-бот (aiogram), который
  обслуживает динамический редирект `/qr` (ссылка с QR-кода на футболке/визитке),
  режим «ивента» с отдельной UTM-меткой, счётчик первых посещений, приём
  результатов опроса посетителей и отправку уведомлений владельцу в Telegram.

Продовый деплой — Docker Compose (`docker-compose.yml`) на собственном VPS
(netcup), nginx как reverse-proxy и TLS-терминатор (`deploy/nginx-suslicke.com.conf`),
с фолбэком: если `hub` недоступен, сам nginx подставляет резервный редирект для
QR-ссылки, чтобы она никогда не «зависала».

## Технологии

- **Frontend (`web/`)**: Next.js 15 (App Router, standalone build), React 19,
  TypeScript, Tailwind CSS 4, `next-intl` (i18n RU/EN), `next-themes`
  (тёмная/светлая тема), Three.js + `@react-three/fiber` + `@react-three/drei`
  (3D-сцена), `motion` (анимации), PostHog (`posthog-js`, аналитика с
  согласием пользователя), генерация QR (`qrcode`), pnpm как пакетный менеджер.
- **Backend (`hub/`)**: Python 3.12, FastAPI, Uvicorn, aiogram 3 (Telegram-бот
  в режиме polling, без вебхука), SQLAlchemy 2 (async) + asyncpg, Postgres 16,
  Pydantic Settings для конфигурации через переменные окружения, pytest для
  тестов.
- **Инфраструктура**: Docker / Docker Compose (три сервиса: `web`, `hub`,
  `postgres`), nginx (TLS через certbot, HTTP-01), собственный VPS (netcup).

## Как это работает (в общих чертах)

1. Пользователь заходит на `suslicke.com` — Next.js-приложение определяет
   локаль и «персону» (по URL или UTM-метке) и показывает соответствующий
   набор секций контента; на фоне рендерится 3D-сцена из частиц (с SVG-фолбэком
   для слабых устройств).
2. Посещения страниц отправляются first-party beacon-запросом на `/api/hit`
   в `hub`, который сохраняет их в Postgres (с учётом персоны, локали, UTM,
   грубой детекцией ботов). Полноценная аналитика (PostHog) подключается
   только после согласия пользователя в баннере cookie-согласия.
3. QR-код на футболке/визитке ведёт на `/qr`: nginx проксирует запрос в `hub`,
   который читает текущую конфигурацию редиректа (обычная ссылка или
   активный «ивент» с отдельной UTM-меткой) из Postgres (с кэшем на 5 секунд
   и хардкод-фолбэком, чтобы редирект никогда не сломался), логирует скан и
   делает 307-редирект. Если `hub` временно недоступен — резервный редирект
   срабатывает прямо на уровне nginx.
4. Владелец управляет режимом «ивента» и настройками QR через Telegram-бота
   (`@suslicke_bot`, aiogram): команды `/qr status|set`, `/event start|stop`,
   `/today` (сводка визитов/сканов/опросов за день). Бот работает в том же
   процессе FastAPI (polling, без публичного вебхука) и присылает владельцу
   уведомления, когда посетитель проходит опрос на странице (`/api/event-survey`).
5. Развёртывание — через `docker-compose.yml` (сервисы `web`, `hub`,
   `postgres`, с фиксированным именем compose-проекта), секреты хранятся в
   `.env` на сервере (не коммитится, доступ chmod 600).
