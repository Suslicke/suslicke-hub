# suslicke.com — личный сайт + hub

## Что это

Личный бренд-проект: публичный сайт **suslicke.com** плюс вспомогательный
бэкенд-сервис **suslicke-hub**, обслуживающий динамическую QR-ссылку на
визитке/футболке, сбор аналитики посещений и Telegram-бота для владельца.
Проект состоит из двух частей, живущих в одном docker-compose стеке:

- **`web/`** — публичный сайт на Next.js 15: мультиязычная (RU/EN)
  персона-ориентированная страница (разный контент под разную аудиторию —
  бизнес, HR, разработчики), анимированная 3D/частицная сцена с силуэтом
  суслика, тёмная/светлая тема, vCard, SEO и аналитика с consent-баннером.
- **`hub/`** — Python-бэкенд на FastAPI + Telegram-бот (aiogram), который
  отдаёт редирект `/qr` с кэшем и UTM-метками, ведёт учёт сканирований QR,
  просмотров страниц и ответов на опрос посетителей, поддерживает «режим
  ивента» с отдельными командами бота.

Продовый деплой — Docker Compose на VPS (netcup), nginx как reverse-proxy и
TLS-терминатор с фолбэком на случай недоступности hub.

## Технологии

**Backend (`hub/`)**: Python, FastAPI, Uvicorn, aiogram 3 (Telegram-бот,
режим polling), SQLAlchemy (async) + asyncpg, PostgreSQL 16 (Alpine), pydantic
/ pydantic-settings (конфигурация и валидация окружения).

**Frontend (`web/`)**: Next.js 15, React 19, TypeScript, Tailwind CSS,
`next-intl` (i18n RU/EN), 3D/частицная графика (Three.js-подход, кастомная
частицная система с одним draw call), PostHog (веб-аналитика с
consent-gate), vCard-роут, JSON-LD/sitemap/robots для SEO.

**Инфраструктура**: Docker / docker-compose (сервисы `web`, `hub`,
`postgres` в одном compose-проекте с явно закреплённым именем `suslicke`),
nginx (reverse-proxy, HTTPS, fallback-редиректы для `/qr` при ошибках
502/503/504), деплой на собственном VPS.

## Как это работает (в общих чертах)

Посетитель сканирует QR-код (на футболке/визитке), попадает по ссылке на
`/qr`, которую обслуживает nginx, проксируя запрос на сервис `hub` (FastAPI).
Hub читает конфигурацию QR-редиректа (модель `QrConfig`) из Postgres с
5-секундным кэшем, чтобы не бить в БД на каждый скан, логирует сам факт
скана (`QrScan`) и делает редирект на целевой URL с нужными UTM-метками.
Если hub недоступен (502/503/504), nginx сам подставляет запасной
(fallback) URL, чтобы ссылка никогда не «зависала» для гостя.

Параллельно в том же процессе hub крутится Telegram-бот на aiogram —
владелец проекта может через чат-команды посмотреть текущий статус QR
(`/qr status`), изменить конфиг (`/qr set`), запустить или остановить
«режим ивента» (`/event start|stop`, отдельная UTM-метка для оффлайн
мероприятий) и получить сводку за день (`/today`).

Публичный сайт (`web/`) — это Next.js-приложение с локализованными
персона-страницами (разный контент под разные аудитории — бизнес, HR,
разработчики), процедурной частицной сценой на фронтенде (силуэт суслика,
который «морфит» в глифы разных персон, реагирует на курсор и клики), формой
опроса посетителей, счётчиком просмотров страниц (`PageView`) и
consent-gated аналитикой через PostHog. Оба сервиса (`web` и `hub`) и
Postgres объединены в один docker-compose стек, который в проде стоит за
nginx с TLS и явной маршрутизацией `/api/` → hub, `/qr` → hub (с fallback),
остальное → статика/Next.js.

## Подробная история изменений (по коммитам)

Всего в репозитории 6 коммитов пользователя, хронологически от старых к
новым. Ниже — детальный разбор, сгруппированный по смысловым темам.

### 1. Backend hub: с нуля — FastAPI + Telegram-бот + Postgres (коммит 48be4732ef)

Первый коммит создаёт новый сервис **suslicke-hub** целиком:

- FastAPI-приложение и aiogram-бот (`@suslicke_bot`, режим polling)
  запущены **в одном процессе**.
- База данных — Postgres 16.
- Модели данных в `hub/app/db.py`:
  - `QrConfig` — конфигурация динамического QR-редиректа;
  - `QrScan` — лог сканирований QR-кода;
  - `SurveyAnswer` — ответы посетителей на опрос;
  - `PageView` — просмотры страниц сайта.
- Роут `/qr` в `hub/app/qr.py`:
  - кэш конфигурации на 5 секунд (чтобы не дёргать БД на каждый скан);
  - фолбэк на дефолтный конфиг, если в БД ничего не настроено.
- Команды Telegram-бота в `hub/app/bot.py`:
  - `/qr status` — посмотреть текущую конфигурацию QR-редиректа;
  - `/qr set` — изменить конфигурацию;
  - `/event start` / `/event stop` — включить/выключить «режим ивента»;
  - `/today` — сводка активности за сегодняшний день.
- `docker-compose.yml` — добавлен с **явно закреплённым именем
  compose-проекта `suslicke`** (важно, чтобы имена volumes/networks не
  зависели от имени директории на сервере).

### 2. Исправление бага конфигурации (коммит a782ca96d0)

- Баг: pydantic не мог распарсить **пустую** переменную окружения
  `ADMIN_CHAT_ID` (типа `int | None`) как `None` — пустая строка вызывала
  ошибку валидации вместо того, чтобы трактоваться как отсутствие значения.
- Исправление в `hub/app/config.py`: добавлен `field_validator`
  `_empty_env_is_none`, который приводит пустую строку к `None` **до**
  основной валидации поля.

### 3. Инфраструктура и nginx-конфигурация (коммит 12a3492290)

- Добавлена конфигурация nginx для домена suslicke.com:
  `deploy/nginx-suslicke.com.conf`.
- HTTPS-терминация на уровне nginx.
- Редирект с `/qr` на fallback-URL при ошибках апстрима 502/503/504 у hub —
  реализовано через именованный location `@qr_fallback`, чтобы QR-ссылка
  никогда не показывала пользователю ошибку.
- Проксирование `/api/` на сервис hub.
- Добавлена временная статическая placeholder-страница
  `deploy/placeholder-index.html` (заглушка, пока фронтенд ещё не готов).

### 4. Frontend suslicke.com: сайт с нуля на Next.js 15 (коммит d94f6593 9a)

Создан с нуля Next.js 15 фронтенд в директории `web/`:

- Персона-ориентированные страницы на русском и английском языках
  (RU/EN) с использованием `next-intl` для интернационализации.
- 3D-сцена героя (`web/src/components/scene/hero-scene.tsx`) с SVG-фолбэком
  на случай, если 3D недоступно/не грузится.
- Consent-gated аналитика на PostHog (аналитика включается только после
  согласия пользователя).
- Hit-beacon — механизм учёта посещений/событий на фронтенде.
- Диалоговое окно опроса посетителей (survey-dialog).
- Роут для отдачи vCard (визитки в электронном виде).
- SEO-инфраструктура: JSON-LD разметка, sitemap, robots.txt.
- Сервис `web` добавлен в `docker-compose.yml`, порт **18000**.

### 5. Редизайн визуального стиля (коммит 1345245245)

Переработка визуального стиля сайта `web/`:

- 3D-сцена (Three.js/react-three-fiber) заменена на кастомную **частицную
  систему** (`suslik-shape.ts`, `shapes.ts`) с **одним draw call** —
  оптимизация производительности рендера.
- Силуэт суслика морфит (плавно трансформируется) в глифы разных персон.
- Реализовано отталкивание частиц от курсора мыши.
- Реализован ripple-эффект (волна) по клику пользователя.
- Реализован gyro-параллакс — реакция сцены на наклон устройства
  (гироскоп, актуально для мобильных).
- Обновлены тексты контента: добавлено 9 бизнес-кейсов и HR-статистика,
  файл `content/facts.ts` и локализационные файлы `messages/*.json`.
- Добавлены новые UI-компоненты: `icons.tsx`, `reveal.tsx` (анимация
  появления), `section-heading.tsx` (заголовки секций).

### 6. Фикс мобильной вёрстки — горизонтальный overflow (коммит e5d482fe8b)

Исправление горизонтального переполнения страницы на мобильных
устройствах:

- Добавлен `overflow-x: clip` в `web/src/app/globals.css`.
- Зафиксирована ширина native-select для переключения персон
  (`h-9 w-28` с `overflow-hidden`) в `site-header.tsx`, чтобы select не
  растягивал документ шире 390px (типичная ширина мобильного экрана).
- Переработан компонент `locale-switch.tsx` под компактную кнопку на
  мобильных устройствах.
- Hover-эффекты карточек вынесены под медиа-запрос
  `@media (hover: hover)`, чтобы они не «залипали» после тапа на
  тач-устройствах (где нет постоянного hover-состояния).

## Итоговая картина

За 6 коммитов пользователь в одиночку спроектировал и реализовал
двухсервисную систему «сайт + бэкенд-хаб» с нуля: полноценный
FastAPI-бэкенд с интегрированным Telegram-ботом и Postgres, продовую
nginx-конфигурацию с отказоустойчивым fallback для критичной QR-ссылки, и
современный Next.js 15 фронтенд с кастомной частицной 3D-графикой,
мультиязычностью, SEO и consent-aware аналитикой — включая последующую
доводку до продакшен-качества (баг-фикс конфигурации, адаптация под
мобильные устройства).
